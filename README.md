# 囲碁 19路盤・15路盤 for Delta Chat

バージョン1.1.0。五目並べアプリのモード選択・CPU戦・オンライン募集の流れを引き継いだ、独立したwebxdcアプリです。元の五目並べのファイルは変更していません。

## ファイルと起動

- `igo-1.1.0.xdc`：Delta Chatに添付するアプリ。
- `igo-1.1.0/`：展開済みソース（index.html、manifest.toml、icon.png）。
- `verification-1.1.cjs`：配布HTMLからロジックを直接読み出す再現用テスト。Node.jsで `node verification-1.1.cjs` を実行します。
- `test-results-1.1.txt`：検証結果。
- `画面_19路盤.png`、`画面_15路盤.png`：375px幅のブラウザ画面。

Delta Chatで相手とのチャットに `.xdc` をファイルとして送信し、投稿のアプリを開きます。解凍は不要です。オンライン対戦する全員が、**同じチャットの同じアプリ投稿**を開いてください。別の投稿に添付し直したものは別の履歴になります。

## 操作

### CPU戦

メニューで自分が黒（先手）か白（後手）かを選び、交点をタップします。CPUは合法手から取り上げや呼吸点を重視する簡易方式です。強い囲碁AIではありません。相手のパス後、または盤の交点数の2倍の手数以降（15路盤450手・19路盤722手）はCPUもパスし、終局できます。CPU戦の途中経過は保存しません。メニューから選び直すと新しい対局になります。

### オンライン

1. 「チャット相手と対戦（オンライン）」を双方で選びます。
2. 一方が「黒で募集」か「白で募集」を押します。
3. 相手が「参加する」を押すと対局開始。黒から交互に打ちます。
4. 石を打つ代わりに「パス」を選べます。「投了」は確認画面で確定します。
5. 終局後、参加者は「もう一度（色を交代）」で同じ相手と即座に再戦できます。相手の承諾画面はありません。

募集者は「募集をやめる」で取り消せます。グループの他のメンバーは観戦できます。参加できるのは先に確定した1人です。同時募集では履歴上の一方の募集を採用します。自動参加はしないので、採用された募集に参加してください。メニューに戻ってもオンラインの対戦は終了しません。終局後は別の2人も新規募集できます。

送信後は更新履歴への反映を待ってください。通信遅延時に同じ操作を連打する必要はありません。受信件数は自分の更新も含み、相手の既読や受領確認を表しません。

## 採用ルール

- メニューの「盤の大きさ」で19路盤（標準・初期値）／15路盤を選択できます。選んでからCPU戦を始めるかオンラインで募集してください。オンライン参加者・観戦者は募集者と同じ盤になります。対局途中の変更はできません。色交代の再戦は同じサイズを維持し、別サイズに変える場合は新規募集の盤選択を使います。
- 盤の大きさにかかわらず、黒先手、白コミ6.5目。置いた石は動かせません。待ったはありません。
- 縦横に同色の石がつながる「連」全体で呼吸点（隣接する空点）を共有します。斜めはつながりません。
- 着手後、呼吸点がなくなった相手の連を取り上げます。その後で自分の連に呼吸点がない手（自殺手）は禁止です。取り上げによって呼吸点ができる手は合法です。
- 単純なコウの取り返しだけでなく、**以前に現れた盤面と同一になる着手すべてを禁止する盤面スーパーコウ**を採用。手番は比較に含めません。初期盤面も履歴に含みます。パスはこの禁止から除外します。
- パスは手番を交代させ、連続2回で得点確認へ進みます。石を打つと連続パス数は0になります。
- 投了した側の負けです。得点確認中でも投了できます。

### 得点・死石・終局確認

中国式を基にした面積計算です。各色の **生きた石の数＋その色だけに接する空点領域の点数** を数え、白に6.5目を加算します。多い側が勝ちです。両方の色に接する空点は中立。黒白どちらにも接しない空点も中立です。取った石の数は記録・表示しますが、得点に別加算しません。

2回のパス後は次の手順で確定します。

1. 取り除く死石をタップします。同じ連全体に×が付きます。再タップすると指定を戻せます。
2. 表示された得点を確認し、両者が「この得点を承認」を押します。
3. 同一の死石指定について両者が承認した時点で終局。指定が変わると承認は両方ともリセットされます。
4. 合意できないときは「対局を再開」。死石指定と承認を破棄し、2回目のパス直後の手番から再開します。スーパーコウの履歴と取り上げ数は維持します。実際に取り切ってから改めてパスしてください。

**死活・セキの自動判定はありません。** セキの石は残してください。空点の所有は上記の隣接色による方式で、セキに関連していても片方の色だけに接する空点は数えます。日本式の地計算ではありません。厳密な中国大会規則の全例外・裁定手順・対局時計などは実装していません。

CPUは死石の交渉をしません。**CPU戦ではあなたの死石指定をそのまま採用し、あなたの承認と同時にCPUも承認します。** CPUが死活を判定した結果ではありません。不明な石は残すか、対局を再開して取り切ってください。死石を不当に指定すると、当然得点も不正確になります。

盤が細かく感じる場合は「盤を拡大」を押してください。盤の内側を縦横にスクロールでき、「盤を全体表示」で戻せます。19路盤の小さい画面ではこの機能を利用してください。

## 表示

- 橙色の点：最後に打った石（パス後は消えます）。
- 上部：自分の色・参加者名・自分の番／相手の番／観戦中。
- 盤面下：手数（パスを含む）、黒白が取った石の数、連続パス数。
- 得点確認中：得点案、死石の×、承認済みの色。

## 履歴と同期

オンラインの状態はwebxdcの更新履歴から全件再構築します。CPU戦の操作は送信しません。更新ごとに一意のイベントID、因果カウンタ、直前の確定イベントID、ゲームID、着手番号を持ちます。参加者・手番・フェーズ・死石指定の版を検証します。重複、古いゲームの操作、同じ手番への重複着手、観戦者の操作、不正な手は採用しません。

端末ごとに異なり得る受信番号ではなく、因果カウンタとイベントIDの共通順序で全履歴を再生するため、**同一の更新集合を受信した端末は同じ状態**になります。同時操作が競合すると一方だけを採用し、もう一方とその操作を前提とした更新は無効になります。遅れて届いた競合更新で盤面が戻る場合があります。最新の盤面・手番を確認して操作し直してください。完全な即時同期を保証するものではありません。履歴の増大に伴い再計算時間も増えます。

本人確認はwebxdcのselfAddrをペイロードに入れて照合する、通常利用向けのものです。更新APIが検証可能な送信者署名をこのアプリに提供するわけではないため、改造アプリによるなりすましや悪意ある履歴改変への強固な認証は実装していません。

## 通常ブラウザのモック

`index.html`を普通のブラウザで開くと自動でテスト表示になります。CPU戦は端末内で遊べます。オンラインの模擬通信は同一オリジンの複数タブでlocalStorageとstorageイベントを使います。HTTPで同じURLを別タブに開く方法が確実です。file://の保存・タブ間共有の可否はブラウザに依存します。別端末との通信には使えません。

モック履歴は同じオリジンのlocalStorageの `igo-v11-mock-log` に保存します。消去するにはサイトデータを削除します。タブのテストIDはsessionStorageです。タブ複製ではIDが引き継がれる場合があるため、新しいタブからURLを開いてください。モックは通信規格の完全なエミュレーターではなく、同時書込の厳密な配送保証もありません。

## 再パッケージ

`.xdc`はZIP形式で、ルートに次の3ファイルだけを格納しています。

```text
index.html
manifest.toml
icon.png
```

webxdc.jsはDelta Chat側が提供するため含めません。外部通信・外部ライブラリ・外部画像は使いません。HTMLに画面・ゲーム処理・CPU・同期・モックがすべて入っています。変更した場合はこの3ファイルをフォルダごとではなく直下に圧縮し、拡張子を.xdcにしてください。

APIとパッケージ形式の参照：[Webxdc公式 Get Started](https://webxdc.org/docs/get_started.html)。
